# Domain 5 — Task Statement 5.1: Explain methods to secure AI systems

## 🎯 Exam Essentials

### **1. AWS Shared Responsibility Model**

- **Concept:** AWS and the customer share responsibility for security and compliance. AWS is responsible for **security of the cloud**, while the customer is responsible for **security in the cloud**.
    
- **Key distinction:** AWS secures the underlying infrastructure; customers securely configure and use AWS services and protect their data.
    
- **Exam trigger:** Look for scenarios asking **who is responsible** for infrastructure, configuration, applications, access, or data security.
    

### **2. AWS Responsibility — Security of the Cloud**

- **Concept:** AWS protects the **global infrastructure**, including Regions, Availability Zones, data centers, physical hardware, networking, and the underlying components that run AWS services.
    
- **Key distinction:** Customers do **not** manage AWS's physical servers, data centers, virtualization layers, or AWS networking components.
    
- **Exam trigger:** If the scenario involves **physical security, data centers, physical servers, host operating systems, virtualization layers, or AWS networking infrastructure**, think AWS responsibility.
    

### **3. Customer Responsibility — Security in the Cloud**

- **Concept:** Customers are responsible for securely using AWS services, including **proper configuration, applications, access controls, and data security**.
    
- **Key distinction:** Moving workloads to AWS does not remove the customer's security responsibilities.
    
- **Exam trigger:** Look for **permissions, encryption, application security, service configuration, or customer data**.
    

### **4. Responsibility Depends on the AWS Service**

- **Concept:** The customer's security-management responsibility varies depending on the service being used.
    
- **Key distinction:** Using a more managed service can reduce the amount of underlying infrastructure that the customer must manage.
    
- **Exam trigger:** Compare a customer-managed infrastructure option such as **Amazon EC2** with a more fully managed option such as **SageMaker Serverless Inference**.
    

### **5. EC2 vs. SageMaker Serverless Inference — Responsibility**

- **Concept:** When deploying an AI model on **Amazon EC2**, the customer is responsible for areas such as the instance operating system, security patches, scaling, and applications running on the instance.
    
- **Key distinction:** With **SageMaker Serverless Inference**, AWS manages the underlying infrastructure, so the customer does not need to manage instances or scaling policies.
    
- **Exam trigger:** If the question emphasizes **minimizing infrastructure management**, recognize the managed-service distinction.
    

### **6. AWS IAM**

- **Concept:** **AWS Identity and Access Management (IAM)** is used to manage and secure access to AWS accounts and resources.
    
- **Key distinction:** IAM controls **who can perform which actions on which AWS resources** through permission policies.
    
- **Exam trigger:** Look for requirements involving **users, permissions, access control, or granting someone access without sharing credentials**.
    

### **7. IAM Is Global**

- **Concept:** IAM is a **global resource**, rather than a resource specific to one AWS Region.
    
- **Key distinction:** Although IAM itself is global, IAM permissions can be configured to **restrict users' access to certain Regions**.
    
- **Exam trigger:** Be careful when a question contrasts **IAM's scope** with the geographic restrictions that can be applied through permissions.
    

### **8. IAM MFA**

- **Concept:** **Multifactor authentication (MFA)** adds an additional authentication factor beyond a username and password.
    
- **Key distinction:** A compromised password alone is insufficient when MFA is enabled because the attacker also needs the numbers generated by the physical or virtual MFA device.
    
- **Exam trigger:** Scenario says an attacker may obtain or guess a **password**, but the organization wants another authentication factor.
    

### **9. IAM Identity Federation**

- **Concept:** IAM supports **identity federation**, allowing users who already have identities/passwords elsewhere to obtain temporary access to AWS.
    
- **Key distinction:** Federation allows existing identities, such as identities from a **corporate network or internet identity provider**, to access AWS without requiring a separate long-term AWS identity in the described scenario.
    
- **Exam trigger:** Look for **existing corporate identities**, an **external identity provider**, or **temporary AWS access**.
    

### **10. AWS Root User**

- **Concept:** The **AWS root user** is the initial identity created with an AWS account and has complete access to AWS services and resources in that account.
    
- **Key distinction:** Root-user permissions **cannot be restricted**, so its credentials require especially strong protection.
    
- **Exam trigger:** If the question asks about the identity with **complete account access whose permissions cannot be restricted**, think root user.
    

### **11. Root User Security Best Practices**

- **Concept:** The transcript recommends protecting the root user with a **strong password and MFA**, never sharing root credentials, and disabling/deleting root access keys because they are not needed for normal activity.
    
- **Key distinction:** The root user should **not be used for everyday AWS tasks**.
    
- **Exam trigger:** Scenario involves securing a newly created AWS account or deciding whether the root user should be used routinely.
    

### **12. IAM Users**

- **Concept:** An **IAM user** is an identity created in AWS representing a person who interacts with AWS services and resources. It consists of a name and credentials.
    
- **Key distinction:** Unlike the root user, an IAM user does not automatically have permissions. A newly created IAM user has **no permissions by default**.
    
- **Exam trigger:** Look for a person who needs specific AWS access and requires their **own credentials and permissions**.
    

### **13. Individual IAM Users**

- **Concept:** The transcript recommends creating **individual IAM users for each person** who needs AWS access, even when multiple people need the same level of access.
    
- **Key distinction:** Sharing credentials removes visibility into **which individual performed an action**.
    
- **Exam trigger:** If several employees share one set of AWS credentials, the key security problem is **loss of individual accountability/visibility**.
    

### **14. Single-Factor vs. Multifactor Authentication**

- **Concept:** Username + password is **single-factor authentication**. MFA adds another authentication factor.
    
- **Key distinction:** A strong password alone still represents a single authentication factor.
    
- **Exam trigger:** If the scenario says the account could still be compromised if the password is stolen or guessed, consider whether **MFA** is needed.

## 🧠 Exam Traps

### **1.**

**Trap:** AWS is responsible for everything related to security because the workload is running in AWS.

**Correct:** Security is **shared**. AWS secures the underlying cloud infrastructure, while the customer remains responsible for securely configuring and using services and protecting customer data.

### **2.**

**Trap:** If you deploy an AI model on EC2, AWS manages the operating system and security patches.

**Correct:** According to the transcript, with **EC2**, the customer is responsible for the instance operating system, security patches, scaling, and applications running on it.

### **3.**

**Trap:** IAM belongs to a specific AWS Region.

**Correct:** **IAM is a global resource**, although permissions can be used to restrict access to particular Regions.

### **4.**

**Trap:** A strong root-user password is sufficient account protection.

**Correct:** The transcript specifically recommends **MFA** for the root user because password-only authentication remains vulnerable if the password is compromised.

### **5.**

**Trap:** IAM users automatically have permissions when created.

**Correct:** A newly created **IAM user has no permissions by default**. Permissions must be granted.

### **6.**

**Trap:** Multiple employees can safely share one IAM user's credentials if they have the same permissions.

**Correct:** Each person should have an **individual IAM user and unique credentials**. Sharing credentials removes visibility into which user performed an action.

### **7.**

**Trap:** The root user should be used for everyday AWS administration because it has all required permissions.

**Correct:** The transcript recommends **not using the root user for everyday tasks** and instead creating IAM users with appropriate permissions.

### **8.**

**Trap:** Identity federation means creating a separate permanent IAM user for every external identity.

**Correct:** The transcript describes federation as allowing users with existing identities elsewhere to obtain **temporary access** to AWS.

### **9.**

**Trap:** MFA prevents someone from discovering your password.

**Correct:** MFA does not prevent password compromise; it provides an **additional authentication factor**, making the password alone insufficient for access.

# 📝 Exam Questions

### **Question 1**

A company is deciding between deploying an AI inference application directly on Amazon EC2 and using SageMaker Serverless Inference. The security team wants to minimize the amount of underlying infrastructure that the application team must maintain. Which approach most directly aligns with this requirement?

A. Deploy on EC2 and have AWS manage the instance operating system and security patches.

B. Deploy on EC2 and have the customer manage the application while AWS manages scaling policies.

C. Use SageMaker Serverless Inference so AWS manages the underlying infrastructure.

D. Use SageMaker Serverless Inference while requiring the customer to manage the underlying inference instances.

**Answer: C — Use SageMaker Serverless Inference so AWS manages the underlying infrastructure.**

**Why:** The transcript specifically distinguishes EC2, where the customer manages the instance environment, from SageMaker Serverless Inference, where AWS manages the underlying infrastructure.

### **Question 2**

An organization has created an AWS account and wants to reduce the risk that compromise of its primary account credentials could result in unrestricted access to AWS resources. Which action is most directly aligned with the security guidance in the lesson?

A. Create an IAM user for everyday tasks and enable MFA for the root user.

B. Create multiple root users so that administrative responsibilities are distributed.

C. Give all administrators access to the root credentials while requiring strong passwords.

D. Replace IAM users with a shared administrative root credential protected by a password manager.

**Answer: A — Create an IAM user for everyday tasks and enable MFA for the root user.**

**Why:** The transcript recommends protecting the root user with MFA and avoiding root-user use for everyday activities.

### **Question 3**

A company employs 20 administrators who all require the same level of AWS access. An administrator proposes creating one IAM user and distributing its credentials to all 20 employees. What security concern does this approach introduce?

A. IAM will automatically prevent the users from accessing the same resources simultaneously.

B. The organization loses visibility into which individual is performing actions in the account.

C. The shared IAM user will automatically inherit root-user permissions.

D. IAM policies cannot grant identical permissions to multiple people.

**Answer: B — The organization loses visibility into which individual is performing actions in the account.**

**Why:** The transcript explicitly recommends individual IAM users because credential sharing prevents identifying which user performed an action.

### **Question 5**

An application team claims that because AWS operates the data centers hosting its AI workload, AWS is responsible for securing the application's data and configuration. According to the Shared Responsibility Model described in the lesson, which statement best addresses the team's claim?

A. AWS secures both the infrastructure and customer applications because the workload runs on AWS.

B. The customer secures the physical infrastructure while AWS configures the customer's applications.

C. AWS secures the underlying cloud infrastructure, while the customer is responsible for securely configuring services and protecting its data.

**Answer: C — AWS secures the underlying cloud infrastructure, while the customer is responsible for securely configuring services and protecting its data.**

**Why:** This is the central distinction between **security of the cloud** and **security in the cloud**.
